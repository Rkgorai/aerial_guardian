# 🛡️ Aerial Guardian

Lightweight multi-object detection and tracking pipeline optimized for aerial/drone imagery. Detects and tracks **persons** from a moving drone platform using **YOLO26s + ByteTrack/BoT-SORT**.

> Built for the VisDrone2019-MOT challenge — balancing inference speed with tracking precision under drone ego-motion, occlusions, and altitude variation.

---

## ✨ Key Features

- **YOLO26s Detection** — Fine-tuned on VisDrone MOT-1 dataset for person detection (9.5M params, ~10MB)
- **Dual Tracker Support** — ByteTrack (speed) or BoT-SORT (accuracy + ReID + camera motion compensation)
- **Ultralytics-Compatible Config** — YAML-based tracker configuration matching Ultralytics defaults
- **Global Motion Compensation** — ORB-based homography estimation for drone ego-motion correction (BoT-SORT)
- **ReID Embeddings** — ResNet18/MobileNetV3 appearance features with HSV histogram fallback (BoT-SORT)
- **Trajectory Visualization** — Bounding boxes, unique IDs, trajectory tails, and FPS overlay
- **Edge-Ready** — Designed for NVIDIA Jetson deployment via TensorRT export

```bash

    --model mot_results/runs/detect/train/weights/best.pt \
    --input test_videos/uav0000086_00000_v.mp4 \
    --output output/result.mp4

    --input test_videos/uav0000086_00000_v.mp4 \

    --model mot_results/runs/detect/train/weights/best.pt \
```

## ⚙️ Tracker Configuration

Both trackers use Ultralytics-compatible YAML configuration files located in `src/trackers/cfg/`.

### ByteTrack (`bytetrack.yaml`)

Fast, IoU-based tracker optimized for speed and crowded scenes.

```yaml
tracker_type: bytetrack
track_high_thresh: 0.25    # Stage 1: high-confidence association threshold
track_low_thresh: 0.1      # Stage 2: low-confidence recovery threshold
new_track_thresh: 0.25     # Minimum confidence to initialize a new track
track_buffer: 30           # Frames to keep lost tracks alive
match_thresh: 0.8          # IoU matching threshold
fuse_score: true           # Fuse detection confidence with IoU
```

### BoT-SORT (`botsort.yaml`)

ByteTrack + ReID appearance features + Global Motion Compensation for drone scenarios.

```yaml
tracker_type: botsort
track_high_thresh: 0.25    # Stage 1 association threshold
track_low_thresh: 0.1      # Stage 2 recovery threshold
new_track_thresh: 0.25     # New track initialization threshold
track_buffer: 30           # Lost track buffer (frames)
match_thresh: 0.8          # IoU matching threshold
fuse_score: true           # Fuse confidence with IoU

# BoT-SORT specific
gmc_method: orb            # Camera motion compensation ['none', 'orb']
proximity_thresh: 0.5      # Spatial gating (IoU distance)
appearance_thresh: 0.25    # Appearance gating (cosine distance)
reid_weights: 'resnet18'   # ReID backbone ['resnet18', 'mobilenet']
```

### Choosing a Tracker

| Feature | ByteTrack | BoT-SORT |
|---------|-----------|----------|
| **Speed** | ⚡ Faster | Slower (ReID + GMC overhead) |
| **Accuracy** | Good | Better (appearance matching) |
| **Camera Motion** | No compensation | ORB-based homography |
| **Re-identification** | IoU only | ResNet18 + HSV fallback |
| **Best For** | Real-time / CPU | Complex motion / GPU |

## 🏗️ Architecture & Design

### Pipeline Flow

```
Input Video
    │
    ▼
┌─────────────────────────┐
│  Frame Extraction       │  cv2.VideoCapture
└────────┬────────────────┘
         │
         ▼
┌─────────────────────────┐
│  YOLO26s Detection      │  Ultralytics inference (conf=0.15, imgsz=640)
│  → [x, y, w, h, conf]  │
└────────┬────────────────┘
         │
         ▼
┌─────────────────────────┐
│  Multi-Object Tracker   │  ByteTrack or BoT-SORT
│  ┌───────────────────┐  │
│  │ Stage 1: High-conf│  │  Match confident detections (≥0.25) with active tracks
│  │ association       │  │
│  ├───────────────────┤  │
│  │ Stage 2: Low-conf │  │  Recover lost tracks with low-conf detections (0.1–0.25)
│  │ recovery          │  │
│  ├───────────────────┤  │
│  │ BoT-SORT only:    │  │  Global Motion Compensation (ORB + RANSAC homography)
│  │ GMC + ReID        │  │  ReID appearance matching (ResNet18 / HSV fallback)
│  └───────────────────┘  │
│  → [x, y, w, h, id, c] │
└────────┬────────────────┘
         │
         ▼
┌─────────────────────────┐
│  Visualization          │  Bounding boxes, ID labels, trajectory tails, FPS overlay
└────────┬────────────────┘
         │
         ▼
    Output Video
```

### 1. Detection — Small Object Optimization

**Base Architecture**: YOLO26s (Ultralytics) — 9.5M parameters, ~10MB model size.

| Strategy | Implementation |
|----------|---------------|
| **Multi-scale Training** | imgsz=640 with random augmentations; close-mosaic at epoch 10 |
| **Heavy Augmentation** | Mosaic, HSV jitter, scale, translation, flip; RandAugment |
| **Low Confidence Threshold** | conf=0.15 for inference (captures small/partial detections) |
| **Anchor-free Head** | Learned anchor boxes from training data distribution |

**Training Details:**
- **Platform**: Kaggle (2x GPU, batch 56)
- **Base Model**: YOLO26s pretrained on COCO
- **Dataset**: MOT-1 dataset (person-focused)
- **Epochs**: 100 (early stopped at 15 via patience=10)
- **Optimizer**: Auto (AdamW)

### 2. Tracking — Addressing ID Switching

ID switching is a major challenge in drone-based tracking due to:
1. **Ego-motion** — Constant camera movement causes unpredictable position changes
2. **Altitude changes** — Objects shrink/grow rapidly
3. **Occlusions** — Trees, buildings, and other passes cause temporary track loss

**Two-stage ByteTrack association:**
```
Stage 1: High-confidence detections (≥0.25) → primary matching with active tracks
Stage 2: Low-confidence detections (0.1–0.25) → recover lost/occluded tracks
```

**Kalman Filter (constant position model):**
- **State vector**: `[x, y, w, h, vx, vy, vw, vh]`
- **No velocity prediction**: Velocity terms are maintained but NOT used for position updates — critical for drone footage where camera ego-motion makes velocity estimates harmful
- **High process noise (Q=0.1)**: Accommodates sudden camera movements

**ID-Switch Prevention:**

| Strategy | Purpose |
|----------|---------|
| **Track Buffer (30 frames)** | Keep lost tracks alive for 30 frames |
| **History-based Re-matching** | Track stores last 30 positions for IoU recovery |
| **Confidence-Gated Init** | New tracks require ≥0.25 confidence |
| **Two-stage Association** | Low-conf detections recover occluded tracks |
| **GMC (BoT-SORT)** | ORB keypoint matching + RANSAC homography compensates camera motion |
| **ReID (BoT-SORT)** | ResNet18 appearance embeddings re-identify tracks after occlusion |

### 3. Edge Deployment (NVIDIA Jetson)

**Optimization Pipeline:**
```
PyTorch Model → FP16 Quantization → TensorRT Engine → Deploy on Jetson
```

**Export & Run:**
```bash
# Export to TensorRT
yolo export model=best.pt format=engine half=True

# Run pipeline with TensorRT engine
python src/pipeline.py --model best.engine --input video.mp4 --output out.mp4
```

**Expected Performance on Jetson:**

| Device | imgsz | Precision | Expected FPS |
|--------|-------|-----------|--------------|
| Jetson Nano (4GB) | 320 | INT8 | ~10–15 |
| Jetson TX2 | 480 | FP16 | ~15–20 |
| Jetson Xavier NX | 640 | FP16 | ~20–30 |
| Jetson Orin Nano | 640 | FP16 | ~30–50 |

**Additional Optimizations:**
1. **INT8 Quantization** — Calibration dataset reduces model to ¼ size
2. **Frame Skipping** — Process every 2nd frame, interpolate tracks
3. **Reduce Input Size** — imgsz=320 gives ~2x speedup with ~10% mAP loss
4. **DeepStream SDK** — Hardware-accelerated pipeline for multi-stream processing
5. **Power Mode** — `nvpmodel -m 0` (MAXN) for best Jetson performance
